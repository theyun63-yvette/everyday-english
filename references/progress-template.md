## Record rules

- Update the self-described level, preferred topics, and matched strategy whenever the learner supplies or changes them.
- Keep self-description separate from the approximate working range; neither is a formal test result.
- Record only errors that are recurring, meaning-changing, target-related, or especially useful.
- Merge duplicates into one pattern rather than listing every occurrence.
- Include a corrected example and a short rule, not only an error label.
- Mark something “mostly mastered” only after successful reuse, not after one explanation.
- Keep the review queue small: normally 3–6 items.
- “Today,” “next day,” and “one week later” are recommended review intervals, not scheduled reminders.
- Tell the learner: “Copy this record if you want to continue with it in a future chat.”
- If no prior record is available, say so plainly and build one from the current session only.

## Active-recall use

When `/review` uses this record:

1. Select 3–5 due or weak items.
2. Ask for recall before showing the answer.
3. Mix formats: translation, correction, completion, scenario response, or paraphrase.
4. Give a hint before a full answer.
5. Update status based on actual reuse: `new` → `improving` → `mostly mastered`.
6. Return a revised portable record only when requested or at the end of the review.
